# Анализ времени выполнения (WCET / BCET)

Вариант: **кодирование сообщения помехоустойчивым кодом** (код Хэмминга).

Программа оценивает время выполнения фрагмента кода в тактах процессора: лучший случай (BCET), наихудший случай (WCET), коэффициент недетерминизма и вклад каждого источника задержек. Если в данных задан дедлайн, проверяет, укладывается ли фрагмент в него в наихудшем случае.

## Модель

Процессор описывается тремя параметрами:

| Параметр | Описание |
|---|---|
| `base_op_cost` | время базовой операции в идеальных условиях, такты |
| `cache_miss_penalty` | штраф за промах кэша при обращении к памяти, такты |
| `branch_mispredict_penalty` | штраф за ошибку предсказания ветвления, такты |

Для каждой операции:

- `BCET = base_op_cost` (данные в кэше, все ветвления предсказаны верно);
- `WCET = base_op_cost + memory_accesses * cache_miss_penalty + branches * branch_mispredict_penalty` (каждое обращение к памяти даёт кэш-промах, каждое ветвление даёт ошибку предсказания).

Для всего фрагмента BCET и WCET суммируются по операциям. Дополнительно считаются:

- коэффициент недетерминизма `WCET / BCET`;
- разбивка WCET на вклад базовых операций, задержек памяти и ошибок ветвления.

## Запуск

Нужен Python 3.9+, сторонние библиотеки не требуются. Запускать из корня проекта:

```
python main.py
```

По умолчанию данные берутся из `data/variant_coding.json`. Другой файл можно передать первым аргументом:

```
python main.py путь/к/файлу.json
```

## Формат входных данных

| Поле | Описание |
|---|---|
| `processor_model` | параметры процессора (см. выше) |
| `deadline_cycles` | дедлайн в тактах; если не указан или равен 0, проверка пропускается |
| `operations[].name` | название операции |
| `operations[].op_type` | тип операции |
| `operations[].memory_accesses` | число обращений к памяти |
| `operations[].branches` | число ветвлений |

## Исходные данные варианта

Параметры процессора: `base_op_cost = 1`, `cache_miss_penalty = 20`, `branch_mispredict_penalty = 10`. Дедлайн: 110 тактов.

| Операция | Тип | Обращений к памяти | Ветвлений |
|---|---|---|---|
| Чтение входных данных | чтение памяти | 2 | 0 |
| Расчет четности P1 | побитовое xor | 0 | 1 |
| Расчет четности P2 | побитовое xor | 0 | 1 |
| Расчет четности P4 | побитовое xor | 0 | 1 |
| Сборка кода Хэмминга | арифметика | 1 | 0 |
| Запись кадра данных | запись памяти | 2 | 0 |

## Результаты

| Операция | BCET | WCET |
|---|---|---|
| Чтение входных данных | 1 | 41 |
| Расчет четности P1 | 1 | 11 |
| Расчет четности P2 | 1 | 11 |
| Расчет четности P4 | 1 | 11 |
| Сборка кода Хэмминга | 1 | 21 |
| Запись кадра данных | 1 | 41 |

Итого по фрагменту:

- BCET = 6 тактов;
- WCET = 136 тактов;
- коэффициент недетерминизма = 22.67;
- вклад базовых операций: 6 тактов;
- вклад задержек памяти (кэш): 100 тактов;
- вклад ошибок ветвления: 30 тактов.

Проверка дедлайна: WCET = 136 > 110, поэтому в наихудшем случае фрагмент **не укладывается** в дедлайн. Основной источник задержек здесь память: 5 обращений дают 100 из 136 тактов.

## Функции

- `load_data_from_json` читает JSON и возвращает модель процессора, список операций и дедлайн.
- `best_case`, `worst_case` считают BCET и WCET одной операции.
- `bcet`, `wcet` считают суммарные значения по фрагменту.

Автор: Митрофанов Д.К.
- `nondeterminism_ratio` считает отношение WCET к BCET.
- `source_breakdown` раскладывает WCET по источникам задержек.
- `main` выводит таблицу и итоговые показатели.
