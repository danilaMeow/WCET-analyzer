# Отчёт по практической работе №2
**Тема:** Оценка времени выполнения программного фрагмента (BCET / WCET)  
**Вариант:** Кодирование сообщения помехоустойчивым кодом (Код Хэмминга)  

---

## 1. Цель работы
Освоение методов анализа времени выполнения программных фрагментов в системах жесткого реального времени с учётом аппаратных факторов детерминизма (кэш-память, предсказание ветвлений).

---

## 2. Исходные данные
- **Модель процессора:**
  - Базовая стоимость операции: 1 такт
  - Штраф за промах кэша: 20 тактов
  - Штраф за ошибку ветвления: 10 тактов
- **Жесткий дедлайн:** 110 тактов

### Список операций фрагмента:
1. `Чтение входных данных` (Память: 2, Ветвления: 0)
2. `Расчет четности P1` (Память: 0, Ветвления: 1)
3. `Расчет четности P2` (Память: 0, Ветвления: 1)
4. `Расчет четности P4` (Память: 0, Ветвления: 1)
5. `Сборка кода Хэмминга` (Память: 1, Ветвления: 0)
6. `Запись кадра данных` (Память: 2, Ветвления: 0)

---

## 3. Результаты расчётов
- **BCET (Наилучшее время):** 6 тактов
- **WCET (Наихудшее время):** 136 тактов
- **Коэффициент недетерминизма (WCET/BCET):** 22.67

### Распределение задержек в WCET:
- Базовые вычисления: **6 тактов** (4.4%)
- Ошибки ветвления: **30 тактов** (22.1%)
- Задержки памяти (кэш): **100 тактов** (73.5%)

---

## 4. Выводы и анализ
1. Проверка дедлайна: Фактическое наихудшее время выполнения (WCET = 136 тактов) превышает максимально допустимый дедлайн (110 тактов). В текущем виде фрагмент не может использоваться в системах жесткого реального времени.
2. Основной вклад в недетерминизм вносят обращения к памяти (73.5% от суммарного времени WCET).
3. Рекомендации по оптимизации: Для снижения WCET рекомендуется использовать блокировку кэш-памяти для критических данных или применить предзагрузку строк кэша.
